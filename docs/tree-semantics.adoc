= Decompose: семантика дерева
:figure-caption: Рисунок

Этот документ фиксирует предметную модель MVP. Геометрия React Flow и результат ELK layout не являются частью этой модели.

== 1. Документ и узел

Каждая схема — отдельный документ Yjs с одним видимым корневым узлом `root`. Идентификатор схемы неизменяем. Для создаваемых схем сервер выдаёт UUID. Основной схемы нет: титульная страница не содержит документа Yjs, а прежний документ `main` удаляется при обновлении. Идентификаторы узлов, порядок, удаления и история действуют только внутри одной схемы. При вставке поддерева через системный буфер все узлы получают свежие ID, в том числе при вставке обратно в исходную схему. Название схемы — текст её корня, отдельного поля названия нет.

Создание схемы выполняется сервером: он инициализирует корень и сохраняет документ до выдачи ссылки. Неизвестный идентификатор при открытии не создаёт документ. Список схем читается из того же хранилища; удаление схем и отдельная сущность workspace не входят в модель.

Минимальная модель узла:

[listing]
----
Node {
  id
  text
  status
  targetTrackerKey?
  placement
  deleted
}

Placement {
  parentId
  placementId
}
----

* `id` неизменяем и уникален в документе;
* `text` — атомарная plain-text строка с мягкими переносами `\n`; CRLF и CR нормализуются в LF, последовательные и завершающие переносы сохраняются;
* `status` принимает только `open` или `done` и изменяется вручную;
* `targetTrackerKey` — необязательная ссылка на дерево задачи по нормализованному ключу трекера;
* `placement` целиком задаёт parent и активную позицию в его порядке детей;
* `deleted` — прежний монотонный tombstone для данных схемы 1; новые удаления представлены независимыми маркерами и допускают undo.

`kind`, координаты, размеры и layout hints в модель MVP не входят.

== 2. CRDT-представление

[listing]
----
meta: Y.Map {
  schemaVersion: 2
  rootId: "root"
}

nodes: Y.Map<Y.Map> {
  [nodeId]: {
    text: string
    status: "open" | "done"
    targetTrackerKey?: string
    placement: { parentId, placementId } | null
    deleted: boolean
  }
}

orders: Y.Map<Y.Array> {
  [parentId]: [{ placementId, nodeId }]
}

deletions: Y.Map<string> {
  [operationId + ":" + nodeId]: nodeId
}

settings: Y.Map {
  textAlign?: "left" | "center"
}
----

Текст редактируется в локальном draft и записывается одной заменой. Awareness используется как мягкая блокировка: если online-участник уже редактирует узел, другой клиент не начинает edit mode. При offline-конфликте Yjs детерминированно выбирает одну строку целиком; посимвольного merge нет.

`targetTrackerKey` хранит не URL, а ключ вида `MC-99636`. У карточки может быть не более одной такой ссылки. Наличие целевой задачи не проверяется: переход по корректному ключу использует обычный маршрут `/tracker/{key}` и при необходимости предлагает создать дерево. Ссылка не встраивает целевой документ, не синхронизирует его состояние и не меняет жизненный цикл исходной схемы. Циклические ссылки между независимыми схемами допустимы.

`settings.textAlign` — общее выравнивание текста схемы, не свойство отдельного узла. Новые обычные схемы и деревья задач создаются со значением `center`; новая схема из GraphML получает то же значение. Собственный файл `.deco` сохраняет записанную в нём настройку, а замена из GraphML по-прежнему задаёт `left`. Отсутствующее или неизвестное значение в ранее сохранённом документе читается как `left`; чтение не записывает значение по умолчанию. Команда `setTextAlign(left|center)` атомарно меняет только эту настройку, без изменения дерева; повтор того же значения не создаёт шаг истории. При concurrent-изменениях Yjs детерминированно выбирает одно значение. Настройка участвует в локальной undo/redo-истории, но её отмена не меняет активный узел. Добавление необязательной карты не требует миграции схемы 2.

Структурная операция вставляет уникальную запись в `orders[parentId]` и одной записью обновляет `placement`. Активной считается только order-запись, совпадающая с текущим `placement` узла. Поэтому concurrent move не создаёт у узла двух родителей, даже если в массивах остаются неактивные записи.

Массив `orders[nodeId]` создаётся вместе с узлом и больше не заменяется. Нельзя лениво создавать его при появлении первого child: два клиента могли бы записать разные `Y.Array` в один ключ и потерять часть видимого порядка. Root и его массив впервые создаёт сервер.

== 3. Инварианты проекции

Для живых узлов доменная проекция обязана обеспечивать:

. Существует ровно один root.
. Root не удаляется, не перемещается и имеет `placement = null`.
. Каждый другой узел имеет ровно одного parent.
. Все узлы достижимы от root.
. Циклов нет.
. Дети каждого parent образуют детерминированный полный порядок.
. Один узел встречается в проекции ровно один раз.

Raw Yjs state может временно содержать конфликтные placements. Проектор не записывает repair обратно в Yjs:

* отсутствующий или удалённый parent заменяется на root;
* в каждом цикле разрывается edge узла с лексикографически максимальным `placementId`;
* восстановленные root children располагаются после обычных root children и сортируются по `nodeId`.

У восстановленного узла может не быть активной order-записи у видимого parent. Перед явной вставкой или перемещением в такой список команда закрепляет восстановленных siblings: записывает их видимый parent и новые placements в текущем projected order. Это часть пользовательской транзакции, а не автоматический repair при merge. Иначе вставка «после восстановленного узла» оказалась бы перед ним. Конкурентное закрепление использует те же правила выбора целого placement.

== 4. Доменные операции

* `createChild(parentId)` создаёт последнего child;
* `createSibling(nodeId)` создаёт следующий sibling;
* `move(nodeId, parentId, index)` создаёт новый placement;
* `reorder(nodeId, delta)` перемещает узел среди siblings;
* `indent(nodeId)` делает предыдущий sibling новым parent;
* `outdent(nodeId)` помещает узел сразу после бывшего parent;
* `setText(nodeId, text)` атомарно заменяет текст;
* `setTrackerLink(nodeId, key|null)` атомарно задаёт или удаляет ссылку на дерево задачи;
* `toggleStatus(nodeId)` переключает `open/done`;
* `insertSubtree(parentId, snapshot)` создаёт копию поддерева последним ребёнком;
* `deleteSubtree(nodeId)` помечает удалёнными все узлы текущего projected subtree.

Локальные операции не разрешают перемещение или удаление root, неизвестный target и цикл относительно текущей проекции.

== 5. Concurrent-семантика

[cols="1,1",options="header"]
|===
| Сценарий | Результат
| Один узел перемещён под разные parents | Выигрывает одно целое значение `placement`
| Разные узлы вставлены в одну позицию | Сохраняются оба; порядок задаёт `Y.Array`
| Concurrent moves образуют цикл | Проектор детерминированно разрывает один edge
| Delete против edit/move наблюдаемого узла | Активный маркер удаления выигрывает
| Два concurrent delete, затем undo одного | Маркер другого удаления остаётся; узел скрыт
| Delete subtree против нового неизвестного child | Новый child сохраняется и восстанавливается под root
| Concurrent edit одной клеточки offline | Остаётся одна целая версия строки без merge
| Concurrent set/remove ссылки одной карточки | Остаётся одно целое значение ключа либо отсутствие ссылки
|===

== 6. Keyboard model MVP

В navigation mode активен один узел. Стрелки навигируют по смысловой структуре, `Enter` создаёт sibling, `Tab` — child, `Ctrl+Up/Down` меняет sibling order, `Ctrl+Right` выполняет indent, `Ctrl+Left` и `Shift+Tab` — outdent, `Space` переключает status, `F2` начинает редактирование. В дереве задачи `F4` открывает параметры карточки, где можно задать или удалить ссылку на другую задачу. `Ctrl+Enter` переходит по ссылке активной карточки, если она задана.

`Delete` и кнопка «Удалить» сразу удаляют выбранный узел со всем поддеревом, без диалога подтверждения. Ошибочное удаление отменяется через undo; root по-прежнему нельзя удалить.

`Ctrl/Cmd+C` записывает в системный буфер снимок активной карточки и её наблюдаемого поддерева. Снимок содержит текст, статус, ссылку на задачу и sibling order, но не содержит координат, presence и Yjs-структур. `Ctrl/Cmd+X` сначала записывает тот же снимок, затем выполняет обычный `deleteSubtree`. Ожидания последующей вставки в документе нет. Если вкладку перезагрузить до undo, восстановление возможно только вставкой из сохранившегося системного буфера. Момента завершения всех параллельных операций не существует: offline-клиент может прислать изменение позднее. Поэтому снимок фиксирует локально наблюдаемое дерево в момент cut. Дети, не наблюдавшиеся в этот момент, обрабатываются обычной concurrent-семантикой удаления.

`Ctrl/Cmd+V` создаёт под активной карточкой новое поддерево со свежими ID. Повторная вставка создаёт ещё одну копию. Cut и paste являются независимыми шагами истории и не образуют общей транзакции между схемами. Корень разрешено копировать как поддерево, но запрещено вырезать. Обычный текст на canvas не создаёт карточку. В textarea работают нативные операции системного буфера.

В editing mode изменения остаются локальными до commit. `Enter`, `Ctrl+Enter` и blur сохраняют текст без создания узла; после `Enter` фокус возвращается на canvas. Только отдельное нажатие `Enter` в navigation mode создаёт sibling. `Tab` сохраняет и создаёт child, `Escape` отменяет draft. Для только что созданного пустого узла `Escape` удаляет узел.

Отмена нового узла не удаляет его, если другой участник уже сохранил его текст или создал в нём детей. При remote delete draft закрывается, focus переходит на следующий живой sibling, предыдущий sibling, parent или root. Remote move сохраняет active node по ID.

`Shift+Enter` вставляет перевод строки в локальный draft штатным действием textarea, сохраняя выделение и нативную историю редактора. Переносы из буфера и импорта сохраняются; длинные строки дополнительно переносятся визуально. Название схемы в верхней панели и списке остаётся однострочным: переносы корневого текста отображаются пробелами, сам текст корня не изменяется. `Shift+Tab` в редакторе сохраняет и выходит из редактирования; `Escape` на canvas переводит фокус на кнопку меню «Действия с клеточкой» в верхней панели. Меню содержит создание child/sibling, редактирование, статус, удаление и отдельную группу «Схема» с настройкой выравнивания текста; из меню `Escape` возвращает фокус на его кнопку. Подсказки о выполненных действиях остаются в невидимой live region для screen reader, без нижнего status bar.

Для изменения размера и focus используются только локальные данные. Presence публикует active/editing node без содержимого draft.

=== Undo/redo

История принадлежит текущей вкладке, хранится в памяти и начинается заново после перезагрузки. `Ctrl/Cmd+Z` отменяет, `Ctrl/Cmd+Shift+Z` или `Ctrl+Y` повторяет действие. Доступны кнопки на панели. В редакторе эти сочетания работают с локальным draft, не с деревом; во время drag история недоступна.

Одна сохранённая замена текста, изменение статуса, ссылки или выравнивания текста схемы, создание, вставка, move/reparent/reorder или удаление поддерева — один шаг `Y.UndoManager`. Cut является удалением, следующая вставка — отдельным шагом. Создание пустого узла и первое сохранение текста — отдельные шаги. Навигация, копирование, вычисленная геометрия, presence и чужие транзакции не входят в историю. Сохранение неизменённого текста или ссылки не создаёт шаг. Новое действие очищает redo. `Escape` при отмене нового пустого узла убирает его создание из истории без возможности восстановить отменённый draft.

Отмена не загружает снимок документа: используется selective undo Yjs с защитой актуальных чужих значений (`ignoreRemoteMapChanges: false`). После remote-конфликтов шаг может примениться частично или быть пропущен; восстановление проигравших версий строк не обещается. Если прежнее значение поля нельзя восстановить из-за конфликта, текущее сохраняется: `deleteFilter` запрещает удалять обязательные поля узла. Инварианты дерева обеспечиваются той же детерминированной проекцией.

Каждое удаление записывает уникальный маркер для каждого наблюдаемого узла поддерева. Узел скрыт, пока присутствует хотя бы один маркер или прежний `deleted = true`. Undo снимает только маркеры своего действия. Неизвестные на момент удаления дети сохраняются по обычным правилам проекции.

Запись узла и его `orders` создаются один раз вне истории, сначала со скрывающим маркером `birth:<nodeId>`. Команда создания снимает этот маркер и вставляет placement в порядок. Вставка поддерева заранее создаёт все raw-записи и внутренние `orders` под такими маркерами, затем одной транзакцией снимает маркеры и добавляет корень копии выбранному parent. Undo создания или вставки возвращает маркеры, но не удаляет raw-узлы. Чужие текст и дети не теряются, дети скрытого родителя проецируются под root. Redo снова показывает те же созданные ID с актуальными данными.

Сервер переводит схему 1 в 2 без переписывания узлов: прежние удаления остаются необратимыми, новые используют `deletions`. После обновления сервера открытые клиенты нужно перезагрузить; первое обновление старого offline-кеша требует соединения. Неизвестные версии схемы сервер отклоняет.

== 7. Перестановка мышью

Drag начинается за любую часть активной некорневой карточки, включая единственного ребёнка. Короткий клик активирует карточку. Перетягивание неактивной карточки перемещает холст без смены активного узла и без доменной операции. Во время редактирования текста drag выключен, чтобы можно было выделять текст мышью.

Drop на тело карточки делает её новым parent и добавляет переносимое поддерево последним ребёнком. Drop в полосе шириной 18 px над или под некорневой карточкой вставляет поддерево соответственно до или после неё. Тело root переносит поддерево на верхний уровень. Сам источник, его потомки и цели, создающие цикл, исключаются. Для sibling-вставки показывается горизонтальная линия, для reparent подсвечивается карточка-родитель. Связь переносимой карточки с прежним parent скрывается во время drag. При допустимой цели вместо неё отображается preview-связь от parent, который будет установлен после drop.

Во время жеста позиция и отметка места вставки локальны, layout зафиксирован, Yjs не получает промежуточные изменения. При отпускании мыши выполняется одна `move(nodeId, parentId, index)`, после чего ELK пересчитывает геометрию. ID и дети перемещаемого узла сохраняются.

`Escape`, отпускание вне допустимой цели и отсутствие изменения структуры не создают доменной операции. Если во время drag другой клиент удалил или переместил источник либо изменил порядок детей затронутого parent, жест отменяется. Устаревший индекс не применяется к новой структуре. Изменение текста, статуса или ссылки не отменяет drag.
