= Decompose: семантика дерева
:figure-caption: Рисунок

Этот документ фиксирует предметную модель MVP. Геометрия React Flow и результат ELK layout не являются частью этой модели.

== 1. Документ и узел

В MVP существует один документ `main` и один видимый корневой узел с идентификатором `root`.

Минимальная модель узла:

[listing]
----
Node {
  id
  text
  status
  placement
  deleted
}

Placement {
  parentId
  placementId
}
----

* `id` неизменяем и уникален в документе;
* `text` — атомарная plain-text строка;
* `status` принимает только `open` или `done` и изменяется вручную;
* `placement` целиком задаёт parent и активную позицию в его порядке детей;
* `deleted` — прежний монотонный tombstone для данных схемы 1; новые удаления представлены независимыми маркерами и допускают undo.

`kind`, координаты, размеры и layout hints в модель MVP не входят.

== 2. CRDT-представление

[listing]
----
meta: Y.Map {
  schemaVersion: 2
  rootId: "root"
}

nodes: Y.Map<Y.Map> {
  [nodeId]: {
    text: string
    status: "open" | "done"
    placement: { parentId, placementId } | null
    deleted: boolean
  }
}

orders: Y.Map<Y.Array> {
  [parentId]: [{ placementId, nodeId }]
}

deletions: Y.Map<string> {
  [operationId + ":" + nodeId]: nodeId
}
----

Текст редактируется в локальном draft и записывается одной заменой. Awareness используется как мягкая блокировка: если online-участник уже редактирует узел, другой клиент не начинает edit mode. При offline-конфликте Yjs детерминированно выбирает одну строку целиком; посимвольного merge нет.

Структурная операция вставляет уникальную запись в `orders[parentId]` и одной записью обновляет `placement`. Активной считается только order-запись, совпадающая с текущим `placement` узла. Поэтому concurrent move не создаёт у узла двух родителей, даже если в массивах остаются неактивные записи.

Массив `orders[nodeId]` создаётся вместе с узлом и больше не заменяется. Нельзя лениво создавать его при появлении первого child: два клиента могли бы записать разные `Y.Array` в один ключ и потерять часть видимого порядка. Root и его массив впервые создаёт сервер.

== 3. Инварианты проекции

Для живых узлов доменная проекция обязана обеспечивать:

. Существует ровно один root.
. Root не удаляется, не перемещается и имеет `placement = null`.
. Каждый другой узел имеет ровно одного parent.
. Все узлы достижимы от root.
. Циклов нет.
. Дети каждого parent образуют детерминированный полный порядок.
. Один узел встречается в проекции ровно один раз.

Raw Yjs state может временно содержать конфликтные placements. Проектор не записывает repair обратно в Yjs:

* отсутствующий или удалённый parent заменяется на root;
* в каждом цикле разрывается edge узла с лексикографически максимальным `placementId`;
* восстановленные root children располагаются после обычных root children и сортируются по `nodeId`.

У восстановленного узла может не быть активной order-записи у видимого parent. Перед явной вставкой или перемещением в такой список команда закрепляет восстановленных siblings: записывает их видимый parent и новые placements в текущем projected order. Это часть пользовательской транзакции, а не автоматический repair при merge. Иначе вставка «после восстановленного узла» оказалась бы перед ним. Конкурентное закрепление использует те же правила выбора целого placement.

== 4. Доменные операции

* `createChild(parentId)` создаёт последнего child;
* `createSibling(nodeId)` создаёт следующий sibling;
* `move(nodeId, parentId, index)` создаёт новый placement;
* `reorder(nodeId, delta)` перемещает узел среди siblings;
* `indent(nodeId)` делает предыдущий sibling новым parent;
* `outdent(nodeId)` помещает узел сразу после бывшего parent;
* `setText(nodeId, text)` атомарно заменяет текст;
* `toggleStatus(nodeId)` переключает `open/done`;
* `deleteSubtree(nodeId)` помечает удалёнными все узлы текущего projected subtree.

Локальные операции не разрешают перемещение или удаление root, неизвестный target и цикл относительно текущей проекции.

== 5. Concurrent-семантика

[cols="1,1",options="header"]
|===
| Сценарий | Результат
| Один узел перемещён под разные parents | Выигрывает одно целое значение `placement`
| Разные узлы вставлены в одну позицию | Сохраняются оба; порядок задаёт `Y.Array`
| Concurrent moves образуют цикл | Проектор детерминированно разрывает один edge
| Delete против edit/move наблюдаемого узла | Активный маркер удаления выигрывает
| Два concurrent delete, затем undo одного | Маркер другого удаления остаётся; узел скрыт
| Delete subtree против нового неизвестного child | Новый child сохраняется и восстанавливается под root
| Concurrent edit одной клеточки offline | Остаётся одна целая версия строки без merge
|===

== 6. Keyboard model MVP

В navigation mode активен один узел. Стрелки навигируют по смысловой структуре, `Enter` создаёт sibling, `Tab` — child, `Ctrl+Up/Down` меняет sibling order, `Ctrl+Right` выполняет indent, `Ctrl+Left` и `Shift+Tab` — outdent, `Space` переключает status, `F2` начинает редактирование.

`Delete` и кнопка «Удалить» сразу удаляют выбранный узел со всем поддеревом, без диалога подтверждения. Ошибочное удаление отменяется через undo; root по-прежнему нельзя удалить.

В editing mode изменения остаются локальными до commit. `Enter`, `Ctrl+Enter` и blur сохраняют текст без создания узла; после `Enter` фокус возвращается на canvas. Только отдельное нажатие `Enter` в navigation mode создаёт sibling. `Tab` сохраняет и создаёт child, `Escape` отменяет draft. Для только что созданного пустого узла `Escape` удаляет узел.

Отмена нового узла не удаляет его, если другой участник уже сохранил его текст или создал в нём детей. При remote delete draft закрывается, focus переходит на следующий живой sibling, предыдущий sibling, parent или root. Remote move сохраняет active node по ID.

В MVP текст представляет один логический абзац: переводы строк при вставке заменяются пробелами, длинные строки переносятся визуально. `Shift+Tab` в редакторе сохраняет и выходит из редактирования; `Escape` на canvas переводит фокус на кнопку меню «Действия с клеточкой» в верхней панели. Меню содержит создание child/sibling, редактирование, статус и удаление; из меню `Escape` возвращает фокус на его кнопку. Подсказки о выполненных действиях остаются в невидимой live region для screen reader, без нижнего status bar.

Для изменения размера и focus используются только локальные данные. Presence публикует active/editing node без содержимого draft.

=== Undo/redo

История принадлежит текущей вкладке, хранится в памяти и начинается заново после перезагрузки. `Ctrl/Cmd+Z` отменяет, `Ctrl/Cmd+Shift+Z` или `Ctrl+Y` повторяет действие. Доступны кнопки на панели. В редакторе эти сочетания работают с локальным draft, не с деревом; во время drag история недоступна.

Одна сохранённая замена текста, изменение статуса, создание, move/reparent/reorder или удаление поддерева — один шаг `Y.UndoManager`. Создание пустого узла и первое сохранение текста — отдельные шаги. Навигация, layout, presence и чужие транзакции не входят в историю. Сохранение неизменённого текста не создаёт шаг. Новое действие очищает redo. `Escape` при отмене нового пустого узла убирает его создание из истории без возможности восстановить отменённый draft.

Отмена не загружает снимок документа: используется selective undo Yjs с защитой актуальных чужих значений (`ignoreRemoteMapChanges: false`). После remote-конфликтов шаг может примениться частично или быть пропущен; восстановление проигравших версий строк не обещается. Если прежнее значение поля нельзя восстановить из-за конфликта, текущее сохраняется: `deleteFilter` запрещает удалять обязательные поля узла. Инварианты дерева обеспечиваются той же детерминированной проекцией.

Каждое удаление записывает уникальный маркер для каждого наблюдаемого узла поддерева. Узел скрыт, пока присутствует хотя бы один маркер или прежний `deleted = true`. Undo снимает только маркеры своего действия. Неизвестные на момент удаления дети сохраняются по обычным правилам проекции.

Запись узла и его `orders` создаются один раз вне истории, сначала со скрывающим маркером `birth:<nodeId>`. Команда создания снимает этот маркер и вставляет placement в порядок. Undo создания возвращает маркер, но не удаляет raw-узел: чужие текст и дети не теряются, дети скрытого родителя проецируются под root. Redo снова показывает тот же ID с актуальными данными.

Сервер переводит схему 1 в 2 без переписывания узлов: прежние удаления остаются необратимыми, новые используют `deletions`. После обновления сервера открытые клиенты нужно перезагрузить; первое обновление старого offline-кеша требует соединения. Неизвестные версии схемы сервер отклоняет.

== 7. Перестановка мышью

Drag начинается за любую часть клеточки и меняет только порядок siblings. Во время редактирования её текста drag выключен, чтобы можно было выделять текст мышью. Root не перетаскивается. Во время жеста позиция и отметка места вставки локальны, layout зафиксирован; Yjs не получает промежуточные изменения. При отпускании мыши выполняется одна `move(nodeId, прежнийParentId, index)`, после чего ELK пересчитывает геометрию. Дети перемещаемого узла сохраняются.

`Escape`, отпускание далеко в стороне от колонки siblings или отсутствие изменения порядка не создают доменной операции. Если во время drag другой клиент удалил/переместил узел либо изменил состав или placements его siblings, жест отменяется: устаревший индекс не применяется к новой структуре. Изменение текста или статуса не отменяет drag.
