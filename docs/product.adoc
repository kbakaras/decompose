= дерево·дел: описание продукта
:figure-caption: Рисунок

== 1. Назначение

дерево·дел (английское название — decompose) — специализированный collaborative-инструмент для декомпозиции больших задач, вопросов, проблем и рассуждений на иерархию более мелких смысловых единиц.

Основной сценарий использования:

. Пользователь создаёт корневой узел, представляющий задачу или предмет размышления целиком.
. Разбивает его на дочерние узлы.
. Продолжает декомпозицию на несколько уровней.
. Меняет порядок элементов по мере осмысления задачи.
. Отмечает состояние отдельных узлов.
. Работает преимущественно с клавиатуры.
. При необходимости делает это одновременно с другими участниками команды.

Инструмент рассчитан прежде всего на небольшую команду разработчиков, максимум — на использование внутри одной компании.

== 2. Почему не обычный mindmap

Decompose визуально может напоминать mindmap, но модель продукта должна быть другой.

Обычный mindmap в первую очередь представляет набор графических узлов и связей. В Decompose узел — это смысловая единица предметной модели.

Прямоугольник на экране — лишь визуальное представление узла.

Например:

* цвет не должен быть единственным носителем статуса;
* положение по вертикали не должно быть единственным носителем порядка;
* связь parent/child должна храниться в модели;
* sibling order должен храниться в модели;
* координаты должны вычисляться layout engine.

== 3. Product philosophy

=== 3.1. Diagram is not the data model

Диаграмма является представлением структуры, а не самой структурой.

=== 3.2. Nodes have meaning

Узел представляет смысловую единицу: задачу, вопрос, решение, проблему, гипотезу, заметку, группу или иной тип, если он будет явно введён в модель.

Не следует заранее считать каждый узел `Task`.

В MVP узел, или клеточка, является минимальной единицей совместного редактирования. Его текст заменяется целиком: совместное посимвольное редактирование одной клеточки не требуется.

=== 3.3. Appearance follows semantics

Цвет, рамка, иконка и прочие визуальные признаки должны по возможности вытекать из семантики узла.

Например:

[listing]
----
status = open  -> yellow
status = done  -> green
----

Но конкретная тема отображения не должна менять смысл данных.

=== 3.4. Structure is first-class data

Parent/child relationship и порядок sibling-узлов являются частью данных.

Layout не должен самопроизвольно менять смысловой порядок детей только ради более красивой картинки.

=== 3.5. Layout is a view

Геометрия вычисляется автоматически.

Пользователь управляет прежде всего:

* структурой;
* порядком;
* семантикой;
* возможно, отдельными layout hints.

Точные координаты узлов не должны быть основной частью предметной модели.

=== 3.6. Keyboard-first

Основные операции должны соответствовать смысловым действиям пользователя:

* создать child;
* создать sibling;
* перейти к parent;
* перейти к child;
* изменить sibling order;
* indent;
* outdent;
* изменить статус;
* начать редактирование текста.

Пользователь не должен ощущать, что он вручную рисует прямоугольники и стрелки.

=== 3.7. Узкая специализация

Decompose не должен превращаться в:

* Miro;
* Jira;
* универсальный diagram editor;
* полноценный project management suite;
* календарь;
* Gantt;
* Scrum board;
* time tracker.

Если позже понадобится связь с внешними системами, предпочтительнее интеграция или ссылка на внешний объект, а не дублирование всей чужой функциональности.

=== 3.8. Простота эксплуатации

Проект должен быть пригоден для self-hosted использования небольшой командой.

Одна сборка и один сервис могут одновременно публиковаться в корне одного hostname и под произвольным префиксом другого. Reverse proxy удаляет префикс перед передачей запросов; отдельная сборка под адрес не нужна. Прямые ссылки и навигация сохраняют корень публикации. Пути схем в этом документе указаны относительно корня приложения, не обязательно корня hostname. Обычный HTTP в доверенной сети поддерживается; offline-перезагрузка оболочки требует localhost или HTTPS.

Приоритет:

* один application service;
* один persistent volume;
* минимальное количество внешней инфраструктуры;
* простой backup;
* простой upgrade.

== 4. Исходные функциональные требования

=== 4.1. Collaboration

* Одновременное редактирование документа несколькими пользователями.
* Участники могут одновременно работать с разными клеточками; текст одной клеточки не объединяется посимвольно.
* Изменения должны сходиться детерминированно.
* Пользователь должен видеть присутствие других участников.
* Желательно отображать, какой узел редактирует другой пользователь.
* В MVP offline-редактирование уже загруженного документа обязательно; новое первое открытие требует сервера.

=== 4.2. Иерархическое представление

* Основной layout — слева направо.
* Узлы одного уровня располагаются по вертикали.
* Пользователь должен явно влиять на порядок sibling-узлов.
* Порядок детей одного parent можно менять клавиатурой или перетаскиванием за любую часть активной клеточки вне редактирования текста. Короткий клик активирует клеточку; перетягивание неактивной перемещает холст, не меняя активную клеточку ни во время жеста, ни после отпускания. Drag не меняет parent.
* Layout engine должен уважать этот порядок.
* Желательно сохранить ощущение стабильности схемы при небольших изменениях, чтобы пользователь не терял mental map.

=== 4.3. Текст в узлах

* Текст переносится автоматически; `Shift+Enter` в редакторе вставляет мягкий перевод строки внутри той же клеточки, без сохранения и создания узла. Переносы при вставке из буфера и импорте также сохраняются. Текст по-прежнему записывается целиком, без rich text.
* Меню «⋯» → «Схема» содержит настройку «Текст карточек по центру». По умолчанию текст выровнен влево; настройка действует на все карточки и их редакторы, сохраняется отдельно для каждой схемы и синхронизируется между участниками. Для изменения нужно представиться; доступны undo/redo и offline-работа.
* Высота узла подстраивается под содержимое.
* В MVP ширина фиксирована: 280 px; высота автоматическая.
* Rich-text в первой версии не требуется.
* Внутри клеточки отображается только её текст, без номера, подписей статуса, участников и служебных сообщений. При наведении на карточку с чужим выделением всплывающая подсказка показывает имена участников, для которых она является текущей. Несколько вкладок одного участника не дублируют его имя; выделение в другой собственной вкладке тоже учитывается. Без чужого выделения подсказки нет. Статус и presence остаются в модели и доступны для screen reader; текст `done` не зачёркивается. Отступы компактные, фон `open` — жёлто-оранжевый, `done` — зелёный.
* Рамка и тень выделения, в том числе при редактировании, соответствуют цвету статуса клеточки.
* Указатель различает действия мышью: открытая ладонь для перемещения холста, сжатая — во время этого жеста; стрелки перемещения только над активной клеточкой с доступной перестановкой; текстовый указатель внутри редактора. Неактивные клеточки, корень и клеточки без возможности перестановки перемещают холст и используют ту же ладонь, что и пустое место.
* Undo/redo отменяет и повторяет собственные действия текущей вкладки: сохранение текста, статус, создание, перемещение и удаление. История не сохраняется после перезагрузки. В редакторе отмена относится к несохранённому тексту; подробная concurrent-семантика описана в xref:tree-semantics.adoc[`tree-semantics.adoc`].
* `Enter` в редакторе сохраняет текст и возвращает навигацию, не создавая узел. Новый sibling создаётся отдельным нажатием `Enter` в режиме навигации.

=== 4.4. Состояние узлов

Минимально нужен явный статус, как минимум эквивалентный:

* open;
* done.

Вероятные дополнительные состояния:

* in-progress;
* blocked;
* irrelevant/cancelled.

Точный набор пока не определён.

=== 4.5. Типы узлов

Вероятные типы:

* task;
* question;
* decision;
* problem;
* hypothesis;
* note;
* group.

Точный набор и необходимость типов вообще ещё требуют отдельного решения.

=== 4.6. Несколько схем

* Название в верхней панели открывает список схем и форму создания. Постоянная дополнительная панель не нужна.
* Каждая системная схема открывается по ссылке `/diagram/{id}`. Корень приложения `/` и `/index.html` показывают титульную страницу с описанием назначения, возможностей и режимов работы. На ней не создаются редактор, документ Yjs и presence. Кнопка «Начать работу» и `Ctrl+O` открывают выбор схемы без блока текущего документа; доступны вкладки «Схемы», «Задачи» и «Файлы». Просмотр страницы и каталога не требует имени. Основной схемы нет; прежний документ `main` удаляется, ссылки на него недействительны. Старые ссылки `/?diagram=<id>` открывают тот же документ и заменяются в адресной строке без дополнительного шага в истории браузера. Параметры дополнительных действий, например `choose=1` для открытия каталога, не выбирают документ.
* Название берётся из текста корня; одинаковые названия допустимы, идентификаторы различаются.
* Текст карточек новой обычной схемы или дерева задачи по умолчанию выровнен по центру. Настройка сохраняется независимо для каждой схемы; ранее созданные схемы без неё остаются с выравниванием влево.
* Данные, presence и undo/redo разных схем изолированы. Переключение внутри приложения и кнопки браузера «Назад»/«Вперёд» меняют схему без перезагрузки страницы и верхней панели. История отмены очищается при смене схемы и reload.
* Надпись «Открываем схему…» появляется только если переход длится не менее 400 мс. При завершении или ошибке она сразу скрывается; новый переход отсчитывает задержку заново. Быстрое переключение не сопровождается вспышкой уведомления и не задерживается ради него.
* Переход по бренду возвращает на титульную страницу, сначала завершая draft и сохранение файла. При ошибке записи можно остаться или явно уйти без сохранения.
* При уходе со схемы её presence и соединение явно закрываются. Имя и цвет участника сохраняются между схемами и перезагрузками в одном профиле браузера; идентичность участника не связана с техническим Yjs ID. В индикаторах участник показывается один раз, даже если у него несколько вкладок; выделение и блокировка редактора учитывают каждую живую вкладку.
* Создание требует соединения с сервером. Уже загруженные схемы доступны offline по своим ссылкам; offline-список использует последний сохранённый перечень и может быть неполным.
* Схемы доступны всем участникам доверенной сети; отдельные workspace и права доступа не предусмотрены. Открытую обычную схему или дерево задачи можно удалить через окно выбора схем после знакомства и подтверждения. Удаление действует для всех, не поддерживает undo и не помещает схему в корзину.

=== 4.7. Имя и гостевой просмотр

* Смотреть схемы, переключаться между ними и перемещать холст можно без имени. Перед первым изменением клеточки или созданием схемы пользователь должен представиться.
* Форма запрашивает только имя: от одного до 80 символов после удаления пробелов по краям. Совпадение имён допустимо и не объединяет разных пользователей. `Enter` подтверждает, `Escape` отменяет без изменения схемы; после подтверждения начатое действие выполняется один раз.
* При drag форма открывается после отпускания карточки, до сохранения порядка. До подтверждения показывается исходная раскладка; перед выполнением повторно проверяется структура. Уход со схемы отменяет отложенное действие.
* Кнопка «Представиться» находится в верхней панели. После знакомства её заменяет собственный значок с инициалами; через него можно изменить имя без переподключения и потери истории отмены. Кнопка доступна и на узком экране.
* Имя, ID и цвет сохраняются между схемами и перезагрузками одного профиля браузера. Изменение имени распространяется на его открытые вкладки. При невозможности сохранить профиль приложение предупреждает, что после reload придётся представиться снова, но позволяет работать.
* Непредставившиеся посетители не имеют индивидуальных значков и не показывают другим выделенные клеточки. Отображается только «Гостей: N» для открытой схемы, включая самого посетителя; несколько вкладок одного браузерного профиля считаются одним гостем. Нулевой счётчик скрыт. После знакомства участник переходит из счётчика в список именованных пользователей.
* Это не аутентификация и не проверка личности. Другой браузер или очистка данных сайта требуют представиться заново; восстановление и перенос идентичности не предусмотрены. Имена не дают дополнительных прав.

=== 4.8. Импорт из yEd

* Действие «Файлы» → «Новая схема из файла» в списке схем принимает файл `.graphml` и создаёт отдельную схему с выравниванием текста по центру. Открытая схема не изменяется. Нужны соединение с сервером и имя пользователя.
* Для замены открытой обычной схемы или дерева задачи выбери «Заменить из файла» и файл `.graphml`. После проверки дерева требуется подтверждение; до него схема не изменяется. ID, URL и привязка к задаче сохраняются, название берётся из импортированного корня, выравнивание становится левым. Действуют те же синхронизация вкладок и сброс undo, что и при замене из `.deco`. Ошибка файла или отмена оставляют схему без изменений.
* Поддерживается одно направленное дерево: единственный корень, один родитель у каждого другого узла, без циклов и недостижимых узлов. Направление связи задаёт родителя и ребёнка, а не декоративные стрелки.
* Переносятся обычный текст, иерархия и вертикальный порядок детей. Порядок определяется центрами узлов сверху вниз, при совпадении — слева направо, затем исходным ID. Точные координаты, размеры и оформление не сохраняются; используется обычная раскладка Decompose.
* Зелёная одноцветная непрозрачная заливка означает `done`, остальные цвета — `open`. Для распознавания зелёного используются оттенки от 70 до 170 градусов включительно и насыщенность от 20 % в модели HSV. Градиенты и неизвестные форматы цвета не распознаются как зелёный.
* Поддерживаются узлы yEd `ShapeNode` и `GenericNode`. Группы, вложенные графы, несколько графов, ненаправленные связи и другие структуры вне дерева отклоняются с объяснением. Частичный импорт не выполняется.
* Ограничения: файл не более 5 МиБ, до 1000 узлов, нормализованные данные запроса не более 1 МиБ. Исходный XML не сохраняется на сервере.
* Импорт — начальное состояние схемы, а не отменяемое действие. Последующее редактирование поддерживает обычные undo/redo.

=== 4.9. Деревья задач трекера

* Адрес `/tracker/MC-99636` открывает единственную схему задачи. При первом открытии она создаётся на сервере после знакомства; отмена не создаёт данных. Существующая схема доступна гостю для просмотра.
* Ключ нормализуется в верхний регистр, соответствует `[A-Z][A-Z0-9]*-[0-9]+` и содержит не более 100 символов. Одному ключу соответствует один документ; конкурентные первые открытия и повторы запроса не создают дубликатов.
* Корень при создании содержит ключ. Затем пользователь заменяет его описанием: название и поисковый текст берутся из корня, отдельного редактируемого `description` нет. Изменение корня не меняет привязанный ключ. Ключ и название показываются вместе; при пустом корне или совпадении названия с ключом ключ показывается один раз.
* В окне выбора есть вкладки «Схемы», «Задачи» и «Файлы»; открывается вкладка текущего режима. Деревья задач исключены из обычного списка. Создание обычных схем доступно во вкладке «Схемы»; открытие и импорт файлов — во вкладке «Файлы», доступной из любого режима.
* Поиск задач ищет вхождение в ключ или текст корня без учёта регистра, включая кириллицу. Переводы строк для поиска и названия заменяются пробелами. Поиск не создаёт задач.
* Рядом с поиском задач постоянно видна кнопка «Создать». Она доступна только для корректного ключа без пробелов (включая пробелы по краям), отсутствие которого проверено на сервере отдельным запросом, независимо от страниц поисковой выдачи. Во время проверки, при ошибке или offline кнопка недоступна. Создание выполняется только по явному нажатию; для удалённого дерева сохраняется подтверждение повторного создания. Существующие деревья открываются из списка.
* Без запроса показываются 20 последних изменённых деревьев. Поиск охватывает весь каталог; выдача идёт по 20 результатов с кнопкой «Показать ещё». Порядок — время изменения по убыванию, при совпадении — ключ по возрастанию.
* Создание и сохранённые изменения документа, включая дочерние карточки, определяют время изменения. Открытие, выделение, presence и viewport его не меняют. Offline-правки получают время сохранения на сервере после синхронизации.
* Ранее загруженная задача открывается offline по тому же адресу. Offline-поиск использует отдельный неполный кеш каталога и явно сообщает об этом. Первое открытие неизвестной задачи требует сервера.
* API трекера не используется; существование задачи во внешней системе не проверяется. Привязка обычных схем к задачам не предусмотрена. Запрос имени остаётся правилом интерфейса, не серверной аутентификацией.

== 5. UX-ориентиры

=== Файлы схем

`Ctrl+O` (на macOS — `⌘+O`) открывает выбор схемы из титульной страницы и редактора, в том числе из клеточки: перед открытием текст сохраняется. Пока фокус в приложении, стандартное браузерное открытие файла заменяется этим действием. При уже открытом диалоге сочетание ничего не меняет; удержание клавиш не вызывает повторного открытия. После закрытия выбора фокус возвращается на холст с прежней активной клеточкой, а на титульной странице — на кнопку «Начать работу». Сочетание работает и при русской раскладке.

Диалог управления разделяет действия с текущей схемой и переход к другой. В верхнем блоке показаны режим и название: внутренняя схема, задача с ключом, файл на диске или участие по ссылке. Внутренняя схема и задача имеют одинаковые действия: скачать файл, перенести на диск с удалением внутренней копии, заменить содержимое из DECO или GraphML, удалить. У владельца файла доступны приглашение участников, сохранение как внутренней схемы и скачивание копии; участник по ссылке может скачать копию, но не распоряжается файлом владельца.

Диалог называется «Выбор схемы для редактирования». Зона открытой схемы и её кнопок выделена светло-жёлтым фоном, без рамки и заголовка «Текущая схема»: плашка режима расположена над названием. Длинное название переносится. Кнопки действий размещены одним рядом с переносом при недостатке места.

Поля поиска во вкладках «Схемы» и «Задачи» имеют одинаковые высоту, шрифт и внутренние отступы. Видимых подписей над ними нет; доступные имена сохранены для экранных дикторов. Надпись «Последние изменённые деревья задач» не выводится. Кнопка «Создать» оформлена так же, как кнопки действий с текущей схемой.

Вкладки открытия доступны во всех режимах, без отдельной надписи «Открыть другую»: каталог внутренних схем с созданием, каталог задач с поиском и открытием по ключу, файл на диске или новая внутренняя схема из DECO/GraphML. Выбор другой схемы не означает замену текущей. Замена и перенос запускаются отдельными действиями верхнего блока и требуют подтверждения; скрытой галочки удаления при обычном скачивании нет.

Перед блоком вкладок нет отдельного разделителя. Во вкладке «Схемы» над списком расположено общее поле поиска и названия новой схемы, без видимой подписи; доступное имя сохранено для экранных дикторов. Для поля отключены браузерное автозаполнение, исправления текста и всплывающая валидация формы. Ввод фильтрует названия по вхождению подстроки без учёта регистра; пустое поле показывает весь список. При переключении вкладок ввод сохраняется, при повторном открытии диалога очищается.

Из поля поиска стрелка вниз переводит фокус на первую найденную схему, стрелка вверх — на последнюю; дальше стрелки выбирают строку списка, а `Enter` открывает её. `Enter` непосредственно в поле открывает первый подходящий результат. Если после загрузки каталога совпадений нет, введено непустое название и создание доступно, `Enter` только переводит фокус на «Создать». Создание требует отдельного клика либо нажатия `Enter`/`Space` на кнопке; удержание первого `Enter` не создаёт схему. Кнопка позволяет создать отдельную схему и при существующих совпадениях. Пустое поле, незавершённый ввод через IME и ожидание каталога без результатов не запускают создание. Offline можно искать по сохранённому каталогу и открывать загруженные схемы, но нельзя создавать новые; `Enter` без совпадений оставляет фокус в поиске.

Во вкладке «Задачи» поиск использует те же клавиши: стрелка вниз переводит фокус на первый результат, вверх — на последний, `Enter` открывает первый результат из поля или выбранный из списка. Если результатов нет и создание доступно, `Enter` только фокусирует «Создать»; для создания требуется отдельное нажатие, удержание `Enter` не срабатывает. При ожидании поиска или проверки ключа, некорректном ключе и offline пустая выдача оставляет фокус в поиске. Изменение запроса сразу убирает прежние результаты, чтобы клавиши не открыли задачу из устаревшей выдачи. Ввод через IME не запускает навигацию или создание.

Списки схем и задач имеют одну остановку по `Tab`; следующее нажатие переводит фокус за пределы списка, `Shift+Tab` — к предыдущему элементу управления. Стрелки вверх/вниз выбирают соседнюю строку без открытия схемы, `Home`/`End` — первую/последнюю; на границах переход останавливается. `Enter` открывает выбранную строку. При первом входе выбирается открытая схема, если она есть в выдаче, иначе первая строка; повторный вход возвращает последнюю выбранную строку. После фильтрации исчезнувшая строка заменяется доступной, поиск не теряет фокус. Пустой список пропускается при обходе по `Tab`. Клик и открытие ссылки в другой вкладке сохраняются.

Верхняя граница диалога закреплена относительно окна браузера. При смене вкладки, фильтрации и загрузке списка высота плавно меняется вниз, без перемещения заголовка и вкладок. Высота ограничена экраном; длинное содержимое прокручивается. При системном предпочтении уменьшенной анимации высота меняется без перехода, верхняя граница остаётся на месте.

Варианты открытия оформлены вкладками «Схемы», «Задачи» и «Файлы». При каждом открытии диалога выбирается вкладка режима документа: «Схемы» для внутренней схемы, «Задачи» для дерева задачи, «Файлы» для файла на диске и участия по ссылке. Фокус получает выбранная вкладка. Стрелки влево/вправо и `Home`/`End` перемещают фокус между вкладками, `Enter` или `Space` активируют вкладку, `Tab` переводит фокус в её содержимое. Поиск задач не перехватывает фокус. Переключение вкладок само по себе не меняет открытый документ.

Скачивание копии запускается непосредственно из меню. Открытие файла на диске, создание схемы из файла и замена содержимого сразу вызывают системный выбор файла, без промежуточного окна приложения. При замене после проверки выбранного файла открывается единственное подтверждение с именами источника и назначения. Отмена выбора ничего не меняет и возвращает фокус на холст; ошибки импорта показываются закрываемым сообщением. Подтверждения удаления, переноса с удалением, отключения от файла с завершением совместной сессии и ухода с несохранёнными изменениями сохраняются.

«Сохранить как внутреннюю схему» завершает совместную файловую сессию, сохраняет принятые правки на диск и создаёт независимый внутренний документ из снимка дерева. После успешного создания редактор переключается на него и освобождает файл. Файл остаётся на диске; приглашённые участники не переводятся в созданный документ автоматически. При ошибке файла или сервера переключения нет; завершённую совместную сессию можно опубликовать повторно. Действие требует имени и соединения. Оно не создаёт привязки к задаче.

Скачивание и предложение имени в системном диалоге сохранения используют единственное расширение `.deco`. Содержимое остаётся прежним JSON формата `decompose`, версии 1; `.decompose.json` и `.json` также читаются. Открытие старого файла не переименовывает его автоматически.

Собственный формат `.deco` переносит текст, переводы строк, статусы, иерархию, порядок детей и выравнивание. Сохраняется видимое дерево текущей вкладки, без координат, удалённых клеточек, истории undo, участников и привязки к трекеру. Имя файла предлагается по тексту корня. Скачивание работает без имени и offline; текущий draft перед ним сохраняется в дерево. Лимит файла — 5 МиБ, данные не обрезаются.

Для отдельного действия «Перенести в файл» нужны соединение, имя, поддержка прямой записи и открытая внутренняя схема либо дерево задачи. После подтверждения и выбора файла сервер блокирует изменения, завершает drafts и синхронизирует подключённые вкладки. Браузер записывает согласованный снимок; только после успешного закрытия потока записи сервер удаляет оригинал, а инициатор переходит к автосохранению в выбранный файл. При ошибке исходная схема остаётся; записанный файл может остаться копией. `Ctrl+S` не открывает этот диалог и не удаляет схему.

Отдельное удаление также ждёт синхронизации подключённых вкладок до 15 секунд; при разрыве связи операция отменяется. Остальные вкладки после удаления доступны только для просмотра и скачивания снимка из памяти. Старые offline-правки не восстанавливают схему. После удаления задачи её адрес предлагает явно создать новое дерево с новым ID, а не создаёт его автоматически. Очистка кешей выполняется при получении сведений об удалении; удалить данные из недоступного браузера или чужой резервной копии приложение не может.

Операции с входным файлом имеют разные последствия. Создание и замена принимают `.deco`, прежние `.json` и `.graphml`; редактирование исходного файла на диске — только собственный JSON-формат. Экспорт обратно в GraphML не выполняется.

* Новая схема в системе — независимая копия с новым URL в обычном каталоге. Требуются соединение и имя.
* Замена открытой системной схемы — после подтверждения, блокировки ввода и синхронизации подключённых вкладок. URL и привязка к трекеру сохраняются; история undo сбрасывается. Если участник отключился или не подтвердил синхронизацию за 15 секунд, замена отменяется. Offline-вкладки не блокируют операцию, но их прежние изменения при возвращении изолируются и доступны для скачивания, а не объединяются с новым деревом.
* Файл на диске — единственное постоянное хранилище содержимого. Приложение не создаёт серверную схему или браузерный кеш документа. Автосохранение выполняется через 500 мс после изменения, с максимальной задержкой запуска две секунды при непрерывных изменениях; записи последовательны. `Ctrl+S` завершает draft и сохраняет немедленно. При ошибке файл не считается сохранённым; доступны повтор и скачивание копии. Внешнее изменение файла останавливает автосохранение без молчаливой перезаписи.

Прямая запись требует разрешения пользователя, HTTPS или localhost, File System Access API и Web Locks в браузере. Без них доступны скачивание и импорт копий. Браузер запоминает дескриптор выбранного файла, но не его содержимое. После перезагрузки файл открывается по прежнему адресу; если разрешение утрачено, кнопка «Продолжить работу с файлом» запрашивает его повторно без выбора файла. Удалённый файл или очищенные данные сайта требуют повторного выбора. При аварийном закрытии несохранённые изменения могут потеряться.

Одновременно записывать файл может только одна вкладка приложения в пределах одного origin; повторный выбор того же файла не обходит блокировку. По общей ссылке другая вкладка подключается участником, а не вторым писателем. Блокировка не распространяется на другие браузеры, origins и внешние программы; проверка внешнего изменения перед записью остаётся обязательной.

Локальный адрес `/file/local/{id}` указывает на дескриптор в этом браузере, не на путь файла на диске. Совместная сессия открывается по `/file/session/{id}` с тем же ID: различается только режим открытия. ID создаётся при первом выборе файла и узнаётся при повторном выборе через сохранённый дескриптор; в содержимое файла он не записывается. Старые ссылки с `localFile` и `fileSession` в корне приложения заменяются соответствующими путями без изменения данных. Старый адрес `?localFile=1` ведёт на `/file/local/1` и предлагает повторно выбрать файл.

«Поделиться сессией» показывает постоянную ссылку `/file/session/{id}` для участников, не меняя локальный адрес `/file/local/{id}` владельца. Единый ID сохраняется при перезагрузке, повторном выборе того же файла, завершении сессии и перезапуске сервера. Секрет владельца и привязка к файлу остаются в браузере; сервер сохраняет только ID и проверку секрета, без содержимого файла. Открытие опубликованного файла владельцем восстанавливает совместную работу по прежней ссылке. Для живой комнаты используется её CRDT, а при её утрате создаётся отдельное поколение из сохранённого файла. Внешнее изменение файла останавливает возврат в живую комнату без перезаписи. Владелец, открывший ссылку приглашения при свободной блокировке файла, возвращается на локальный адрес; при занятой блокировке другая вкладка остаётся участником. Восстановление требует соединения с сервером.

В верхней панели вместо отдельного названия схемы отображается голубая плашка «Файл на диске», имя выбранного файла и состояние записи: «Сохранено», «Сохраняем» или «Не сохранено». Вся плашка со стрелкой открывает меню схем; базовая линия её текста совпадает с базовой линией названия «дерево·дел». Ошибка также меняет цвет плашки. У приглашённых участников отображаются метка «По ссылке» и имя файла, без пути к нему и без утверждения о сохранении на их диск. Имя сообщает владелец; после утраты комнаты новая вкладка ожидания показывает только режим и статус до возвращения владельца. Уже полученное имя остаётся видно при приостановке и завершении подключения. На узком экране остаются метка режима и стрелка меню; полные сведения доступны в подсказке и для screen reader. Высота верхней панели не увеличивается. Обычная схема в системе, в том числе импортированная копия файла, такой плашки не имеет.

Сервер передаёт изменения и держит дерево в памяти без записи содержимого в SQLite; только вкладка владельца сохраняет файл. При отсутствии владельца или ошибке записи остальные могут просматривать и скачивать уже открытое дерево, но не изменять его. Владелец может продолжать локальную работу offline. Память комнаты сохраняется до пяти минут отсутствия владельца. Явное завершение приостанавливает совместную работу до повторного открытия файла или приглашения, но не отзывает постоянную ссылку. Свежая вкладка участника без доступной комнаты показывает «Ожидаем владельца файла» и подключается автоматически после её восстановления. Прямой доступ к файлу владельца не предоставляется.

После успешного восстановления владельца нет сообщения о завершённой сессии. При явной приостановке закрываемое сообщение поясняет, что файл сохраняется и ссылка остаётся прежней; его закрытие возвращает фокус на холст. Старые вкладки с уже загруженным снимком не объединяются автоматически с восстановленным поколением: участник может скачать копию своих правок и явно открыть актуальную схему по той же ссылке. Ошибки записи остаются отдельными предупреждениями.

Постоянная привязка требует сохранности базы сервера и данных браузера владельца. Секрет владельца независим от публичного ID; знание ссылки не даёт права открыть сессию от его имени. Миграция прежних раздельных ID и псевдонимы старых приглашений не предусмотрены.

=== Холст и навигация

Холст занимает всю область окна под одной компактной верхней панелью. В ней находятся название документа, соединение и presence, undo/redo, вписывание схемы, справка и меню редких действий с клеточкой. Отдельных полос заголовка, инструментов, слоганов и нижнего status bar нет. Ошибки и предупреждения о занятом редакторе показываются компактным закрываемым уведомлением поверх холста; обычные подсказки не занимают его площадь.

После закрытия списка схем и диалогов открытия, сохранения, удаления или совместной файловой сессии клавиатурный фокус возвращается на холст с сохранением активной клеточки, а не на кнопку выбора схемы. При переходе между диалогами фокус остаётся в открытом диалоге. Кнопка выбора схемы доступна для явной клавиатурной навигации.

Контейнеры диалогов не получают дополнительной браузерной обводки фокуса. Клавиатурный фокус кнопок и ссылок внутри диалогов обозначается внутренним зелёным индикатором, без внешней красно-коричневой рамки. В режиме принудительных системных цветов используется внутренняя контрастная обводка.

Исторически исходный workflow строился вокруг yEd:

* прямоугольники;
* связи;
* иерархия слева направо;
* быстрый автоматический layout;
* возможность влиять на вертикальный порядок;
* хорошая работа с клавиатурой;
* минимальный интерфейсный барьер после привыкания.

Decompose должен сохранить эту скорость, но заменить неявные визуальные договорённости явной семантической моделью и добавить collaboration.

== 6. Название

Русскоязычное название системы — дерево·дел. В верхнем левом углу, заголовке вкладки и сообщении загрузки используется это написание: строчные буквы и средняя точка `·` без пробелов.

Английское название проекта decompose сохраняется. Имена пакета и сервисов, адреса, идентификаторы документов и ключи хранилищ не меняются.
