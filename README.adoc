= дерево·дел (decompose)
:figure-caption: Рисунок

дерево·дел — русскоязычное название небольшого collaborative-инструмента для иерархической декомпозиции задач, вопросов, проблем и рассуждений. Английское название проекта — decompose.

Проект ориентирован прежде всего на использование внутри небольшой команды разработчиков, максимум — внутри одной компании.

Главная идея: узлы на схеме имеют собственную семантику, а визуальное представление лишь отображает эту семантику.

Пример:

* `status = open` может отображаться жёлтым цветом;
* `status = done` может отображаться зелёным цветом;
* порядок дочерних узлов является частью модели;
* координаты прямоугольников вычисляются layout engine и не являются главным источником истины.

== Основные свойства

* одновременное редактирование несколькими пользователями;
* иерархическое представление слева направо;
* быстрый keyboard-first workflow;
* автоматический layout;
* возможность явно управлять порядком sibling-узлов;
* автоматическая подгонка размера узла под текст;
* семантические свойства узлов вместо использования цвета как единственного носителя смысла;
* максимально простое self-hosted развёртывание.

== Название

В русскоязычном интерфейсе используется дерево·дел — со строчных букв, со средней точкой `·` без пробелов.

Английское название decompose сохраняется, как и имя пакета, сервиса, файла `decompose.sqlite` и ключи браузерного хранилища. Переименование интерфейса не требует переноса данных.

== Текущий статус

Реализован MVP: несколько независимых схем, keyboard-first дерево, ручные статусы `open/done`, совместная работа, локальное хранение и SQLite persistence.

Текст клеточки сохраняется целиком. Одновременного посимвольного редактирования нет. При offline-конфликте одной клеточки остаётся одна целая версия; остальные структурные изменения объединяются по правилам xref:docs/tree-semantics.adoc[модели дерева].

== Запуск

Нужен Node.js 24 LTS и npm. Другие major-версии намеренно запрещены, поскольку нативная зависимость `better-sqlite3` привязана к ABI Node.js. Файл `.nvmrc` выбирает нужную версию через nvm, а зависимости закреплены в `package-lock.json`.

[source,shell]
----
nvm use
npm ci
npm run dev
----

Если Node.js 24 ещё не установлен, выполни `nvm install` вместо `nvm use`. После перехода с другой major-версии однократно выполни `npm ci`, чтобы пересоздать `node_modules` для правильного ABI.

Открой `http://localhost:5173`. Vite проксирует API и collaboration на backend `127.0.0.1:3000`.

Production-сборка:

[source,shell]
----
npm run build
npm start
----

Открой `http://localhost:3000`. Первое открытие документа требует доступного сервера. Загруженный документ можно редактировать при потере соединения. Offline-перезагрузка страницы через service worker доступна на localhost и по HTTPS; на обычном HTTP под другим hostname для перезагрузки нужен сервер.

=== Docker Compose

Опубликованный образ можно запустить с помощью следующего файла. Сохрани его как `compose.yaml` или `docker-compose.yaml`.

.Полный пример `compose.yaml`
[source,yaml]
----
services:
  decompose:
    image: ${DECOMPOSE_IMAGE:-kbakaras/decompose:latest}
    ports:
      - "${DECOMPOSE_BIND_ADDRESS:-127.0.0.1}:${DECOMPOSE_PORT:-3000}:3000"
    environment:
      DATA_DIR: /data
    volumes:
      - decompose-data:/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:3000/healthz').then(r => { if (!r.ok) process.exit(1) }).catch(() => process.exit(1))"]
      interval: 30s
      timeout: 5s
      start_period: 10s

volumes:
  decompose-data:
----

Если репозиторий `kbakaras/decompose` в Docker Hub закрытый, сначала выполни `docker login` с учётной записью, которой разрешено скачивание образа. Затем запусти приложение из каталога с Compose-файлом:

[source,shell]
----
docker compose pull
docker compose up -d
docker compose ps
----

По умолчанию приложение доступно по адресу `http://127.0.0.1:3000`. Внешний порт можно изменить без правки файла:

[source,shell]
----
DECOMPOSE_PORT=8080 docker compose up -d
----

В этом случае адрес приложения — `http://127.0.0.1:8080`. Порт контейнера остаётся равным `3000`. Чтобы разрешить подключения из доверенной локальной сети, отдельно измени адрес привязки:

[source,shell]
----
DECOMPOSE_BIND_ADDRESS=0.0.0.0 DECOMPOSE_PORT=8080 docker compose up -d
----

[WARNING]
====
В MVP нет аутентификации и разграничения доступа. Не публикуй порт приложения напрямую в интернете или другой недоверенной сети.
====

Для постоянных настроек создай рядом с Compose-файлом файл `.env`, который Docker Compose прочитает автоматически:

[source,dotenv]
----
DECOMPOSE_IMAGE=kbakaras/decompose:1.2.3
DECOMPOSE_BIND_ADDRESS=127.0.0.1
DECOMPOSE_PORT=8080
----

По умолчанию используется образ `kbakaras/decompose:latest`. Конкретную версию также можно закрепить для одного запуска:

[source,shell]
----
DECOMPOSE_IMAGE=kbakaras/decompose:1.2.3 docker compose up -d
----

Каталог `/data` подключён как named volume `decompose-data`. В нём находятся база `/data/decompose.sqlite` и служебные файлы SQLite. Монтируй весь каталог `/data`, а не отдельный файл базы. `docker compose down` останавливает и удаляет контейнер, но сохраняет volume. Команда `docker compose down -v` удаляет volume вместе со всеми схемами, поэтому её нельзя использовать при обычном обновлении.

[#system-backup]
==== Системное резервное копирование

Страница `/backup` создаёт переносимый ZIP с обычными схемами и деревьями задач. Такой архив удобен для выборочного восстановления и переноса данных, но не содержит всего состояния сервера. Полная резервная копия экземпляра должна сохранять весь каталог `/data`: в него входят документы, каталог схем, привязки задач и служебные данные файловых сессий.

Для небольшой установки самый простой надёжный способ — ненадолго штатно остановить приложение и выгрузить named volume в архив на хосте. Не копируй файлы работающей базы SQLite обычной файловой командой: полученная копия может не соответствовать одному согласованному состоянию базы.

Следующий сценарий запускается из каталога с Compose-файлом. Он останавливает сервис, архивирует тот же volume через одноразовый контейнер и запускает сервис даже при ошибке резервного копирования. Каталог назначения можно задать через `DECOMPOSE_BACKUP_DIR`:

[source,bash]
----
set -euo pipefail

backup_dir="${DECOMPOSE_BACKUP_DIR:-./backups}"
backup_file="$backup_dir/decompose-system-$(date -u +%Y-%m-%d_%H-%M-%SZ).tar.gz"
mkdir -p "$backup_dir"

restart_decompose() {
  docker compose start decompose
}
trap restart_decompose EXIT

docker compose stop -t 30 decompose
docker compose run --rm --no-deps -T --entrypoint tar decompose \
  -czf - -C /data . > "$backup_file"
gzip -t "$backup_file"

docker compose start decompose
trap - EXIT
printf 'Создана резервная копия: %s\n' "$backup_file"
----

Архив находится вне Docker volume, поэтому его может забирать обычная система резервного копирования. Вместе с ним сохраняй Compose-файл и `.env` с точным тегом образа. Для предсказуемого восстановления сначала запускай ту же версию приложения, проверяй данные и только затем обновляй образ. Тег `latest` не фиксирует версию и для этой цели не подходит.

Храни хотя бы одну копию на другом носителе или узле, контролируй завершение задания по коду возврата и периодически проверяй восстановление. Архив может содержать рабочие данные команды, поэтому ограничь доступ к нему и включи шифрование в системе резервного копирования.

Перед восстановлением проверь архив и сделай отдельную копию заменяемого состояния. Восстановление полностью очищает `/data`, распаковывает архив и только после этого запускает приложение:

[source,bash]
----
backup_file=./backups/decompose-system-2026-09-22_01-30-00Z.tar.gz
gzip -t "$backup_file"

docker compose pull
docker compose create decompose
docker compose stop -t 30 decompose
docker compose run --rm --no-deps -T --entrypoint node decompose \
  -e "const fs = require('node:fs'); for (const name of fs.readdirSync('/data')) fs.rmSync('/data/' + name, { recursive: true, force: true })"
docker compose run --rm --no-deps -T --entrypoint tar decompose \
  -xzf - -C /data < "$backup_file"
docker compose up -d
docker compose ps
----

После восстановления проверь `/healthz`, открой несколько обычных схем и деревьев задач. Внешние файлы `.deco` не находятся в `/data` и должны входить в резервное копирование тех каталогов, где они сохранены. Профиль пользователя и секрет владельца файловой сессии хранятся в данных браузера, поэтому серверный архив их не восстанавливает.

Если очистка или распаковка завершилась ошибкой, не запускай приложение поверх частично восстановленного каталога. Устрани причину и повтори восстановление из проверенного архива.

Для обновления скачай образ и пересоздай контейнер. Существующий volume подключится снова:

[source,shell]
----
docker compose pull
docker compose up -d
----

Локальная Docker-сборка имеет версию `local`:

[source,shell]
----
docker build --build-arg APP_VERSION=local -t kbakaras/decompose:local .
DECOMPOSE_IMAGE=kbakaras/decompose:local docker compose up -d
----

Версия сборки отображается внизу титульной страницы. Релизный образ получает её из Git-тега вида `v1.2.3` и показывает без начальной `v`.

=== Публикация образа

GitHub Actions проверяет каждый push в `main`: устанавливает зависимости, запускает тесты, собирает приложение и проверяет Docker-сборку без публикации. Образ отправляется в Docker Hub только по SemVer-тегу с начальной `v`.

[source,shell]
----
git tag v1.2.3
git push origin v1.2.3
----

Стабильный тег публикует `kbakaras/decompose:1.2.3` и обновляет `kbakaras/decompose:latest`. Тег вида `v1.2.3-rc.1` публикует только `1.2.3-rc.1`. Для записи в Docker Hub секрет репозитория GitHub `DOCKERHUB_WRITE` должен содержать access token пользователя `kbakaras` с правом push.

=== Reverse proxy и обычный HTTP

Одна сборка и один экземпляр сервиса могут одновременно обслуживать корень сайта и подпуть на другом hostname, по HTTP или HTTPS. Например, `http://decompose.test/` и `http://gateway.test/decompose/`. Для этого не нужны `BASE_PATH`, build arguments или повторная сборка под префикс.

Frontend собирается с относительными адресами ресурсов. Сервер указывает в HTML относительный путь к корню приложения; браузер разрешает его с сохранением внешнего hostname, порта и префикса. API, ссылки, логотип и WebSocket используют этот базовый URL. При прямом открытии `/decompose/tracker/MC-99636` ресурсы загружаются из `/decompose/assets/`, API — из `/decompose/api/`, WebSocket — из `/decompose/collaboration`. Для HTTP используется `ws`, для HTTPS — `wss`.

Пример Caddy: обе HTTP-публикации в доверенной сети ведут в один backend.

[source,caddyfile]
----
http://decompose.test {
    reverse_proxy 127.0.0.1:3000
}

http://gateway.test {
    redir /decompose /decompose/?{query} 308

    handle_path /decompose/* {
        reverse_proxy 127.0.0.1:3000
    }
}
----

Имена должны разрешаться в адрес компьютера с Caddy. `handle_path` удаляет `/decompose` перед передачей HTTP-запроса или WebSocket upgrade upstream. Backend по-прежнему получает `/api/...`, `/collaboration` и `/tracker/...`. Редирект добавляет завершающий слеш к корню публикации, сохраняя query. Для другого префикса измени только правила Caddy; сохранять префикс в upstream-запросах не нужно.

Адрес upstream относится к серверу, а не к браузеру; если Caddy работает в отдельном контейнере, укажи доступный ему адрес сервиса. Для HTTPS используй свой hostname с корректно настроенным DNS и сертификатом. Дополнительные `header_up`, в том числе `X-Forwarded-Prefix`, не нужны.

Backend не ограничивает hostname и не использует forwarded-заголовки для авторизации или построения ссылок. CORS-разрешения и глобальное доверие proxy не включены. Ограничение доступа остаётся задачей доверенной сети или reverse proxy; HTTPS сам по себе не добавляет аутентификацию.

Для UUID используется `crypto.randomUUID()`, если метод доступен; иначе — `crypto.getRandomValues()` с формированием UUID v4. Поэтому обычный HTTP не требует `randomUUID()`. Если оба метода недоступны, генератор выдаёт ошибку о невозможности безопасной генерации идентификаторов: браузер без Web Crypto не поддерживается, замены через `Math.random()` нет.

Профиль пользователя и локальный кеш привязаны к origin. При смене hostname, протокола или порта нужно представиться заново; серверные схемы остаются в той же SQLite. Service worker ограничен корнем конкретной публикации и не удаляет кеши других scope. Несколько независимых backend на одном origin не изолированы по браузерным данным; описанная конфигурация публикует один backend.

Ручная проверка после `npm run build` и `npm start`:

. Открой `http://localhost:3000`, представься и создай схему с дочерней карточкой. Перезагрузи страницу и проверь сохранность данных.
. Открой одну схему по `http://decompose.test/diagram/<id>` и `http://gateway.test/decompose/diagram/<id>`, представься на обоих адресах и измени карточку. Проверь синхронизацию между вкладками и reload.
. В Network на втором адресе все ресурсы, API и WebSocket должны сохранять `/decompose/`, соединение `/decompose/collaboration` — получать ответ `101`. `window.isSecureContext` должен быть `false`, а создание карточек — работать.
. В новой вкладке напрямую открой `/decompose/tracker/MC-99636`, затем переключись на обычную схему и проверь «Назад»/«Вперёд», reload и ссылку логотипа. Ресурсы не должны запрашиваться из `/assets/` или `/decompose/tracker/assets/`.
. Повтори проверку через HTTPS и нестандартный внешний порт: сокет должен использовать `wss` для HTTPS и сохранять внешний порт. На localhost или HTTPS после первой загрузки проверь offline reload вложенной ссылки.

== Команды и конфигурация

[cols="1,1",options="header"]
|===
| Команда | Назначение
| `npm run dev` | Backend и frontend с перезапуском при изменениях
| `npm run typecheck` | Проверка TypeScript
| `npm test` | Доменные, property-based, layout и SQLite integration-тесты
| `npm run build` | Проверка типов и сборка клиента/сервера
| `npm start` | Запуск production-сборки
| `npm run test:e2e` | Chromium: клавиатура, два клиента, soft lock, offline и reload
|===

Перед браузерными тестами выполни `npm run build` и `npx playwright install --with-deps chromium`. Тесты используют отдельную временную SQLite-базу, порт 4173 для единственного backend и 4183 для тестового reverse proxy. Production service worker намеренно не включён в Vite dev server.

Проверки HTTP и reverse proxy: `npm test -- tests/unit/uuid.test.ts tests/unit/client-addresses.test.ts tests/unit/proxy.test.ts`, затем `npm run build` и `npm run test:e2e -- tests/e2e/http-host.spec.ts`. Браузерный тест сам направляет `decompose.test` на loopback через resolver Chromium, не изменяя системный DNS и не включая secure context.

Проверки одной сборки на разных путях: `npm run test:e2e -- tests/e2e/base-path.spec.ts`. Стенд направляет `decompose.test` и `gateway.test` на один proxy, публикующий тот же backend из корня и под префиксом. Маленькая отдельная fixture проверяет загрузку динамических JS/CSS chunks; production-файлы не пересобираются под адрес публикации.

`DATA_DIR` задаёт каталог SQLite (по умолчанию `./data`), `PORT` — порт (3000), `HOST` — адрес (127.0.0.1, в Docker 0.0.0.0). Порядок системного резервного копирования всего каталога описан в разделе <<system-backup,«Системное резервное копирование»>>. При обновлении сохрани volume, скачай нужный образ и перезапусти сервис. Сервер автоматически переводит схему 1 в 2 (маркеры удаления для undo); старые удаления остаются необратимыми. После обновления перезагрузи открытые вкладки с подключением к серверу. Другие неподдерживаемые версии схемы отклоняются.

== Управление

=== Сохранение схемы в файл

Скачивание копии выполняется одним нажатием в меню. Действия открытия, импорта и замены сразу вызывают системный выбор файла. Для замены подтверждение появляется только после выбора и проверки файла; до него открытая схема не меняется.

Нажми название схемы в верхней панели или `Ctrl+O`. Сверху находятся режим, название и действия с текущей схемой, снизу — вкладки «Схемы», «Задачи» и «Файлы». Этот переход доступен в любом режиме; открытие другой схемы не заменяет текущую. Во вкладке задач можно найти дерево или создать его по ключу кнопкой «Создать» рядом с поиском. Кнопка доступна для корректного ключа без пробелов, например `MC-99636`, если сервер подтвердил отсутствие дерева. Поиск сам по себе ничего не создаёт.

«Сохранить в файл» скачивает копию `.deco`, не меняя место хранения. Для системной схемы `Ctrl+S` или `⌘+S` сохраняет копию без диалога и без удаления, включая текущий текстовый draft; в файловом режиме сочетание записывает выбранный файл. Файл содержит видимое дерево, статусы, порядок детей и выравнивание; координаты, undo, удалённые узлы и участники не экспортируются. Ограничение — 5 МиБ, без обрезки данных. Старые `.decompose.json` и `.json` по-прежнему открываются; формат содержимого не меняется.

Отдельное действие «Перенести в файл» переносит открытую внутреннюю схему или дерево задачи во внешний файл. Нужны имя, соединение, HTTPS или localhost и браузер с прямой записью файлов. После подтверждения и выбора файла приложение синхронизирует и блокирует подключённые вкладки, записывает окончательный снимок и только после успешной записи удаляет серверную копию. Затем продолжается автосохранение в выбранный файл. Другие участники не переходят в файловую сессию автоматически.

При ошибке записи, отмене или отключении участника схема остаётся в системе. Подготовка ждёт синхронизации до 15 секунд, затем на запись и подтверждение есть до 60 секунд. Если файл записался, а удаление не завершилось, он остаётся копией; проверь сообщение перед повтором. При потере ответа приложение проверяет результат удаления на сервере. На обычном HTTP перенос недоступен: можно скачать копию, проверить её самостоятельно и отдельно удалить схему.

«Удалить схему» в том же блоке удаляет открытую обычную схему или дерево задачи для всех участников после подтверждения внутри приложения. Нужны имя и соединение. Корзины и undo удаления схемы нет. Подключённые вкладки завершают drafts; отключение или тайм-аут отменяет удаление. Остальным участникам остаются просмотр и скачивание снимка из памяти. При получении уведомления очищаются локальные кеши документа; недоступные браузеры узнают об удалении после подключения. Это не гарантированное стирание чужих копий или резервных копий SQLite.

Адрес удалённой задачи показывает кнопку «Создать новое дерево». Только нажатие создаёт пустое дерево с ключом в корне и другим ID. Старые offline-правки не восстанавливают удалённую схему и не попадают в новое дерево.

В разделе «Файлы» доступны «Открыть файл на диске» для автосохранения в исходный файл и «Новая схема из файла» для создания внутренней копии. Новая копия не наследует привязку к задаче трекера. «Заменить из файла» в действиях текущей схемы сохраняет URL и существующую привязку, но сбрасывает undo. Перед заменой можно скачать прежнюю схему; подтверждение открывается внутри приложения. Подключённые вкладки завершают drafts и подтверждают синхронизацию. При отключении участника или отсутствии подтверждения за 15 секунд замена отменяется. Вернувшаяся offline-вкладка предлагает скачать прежнее состояние и открыть актуальное, не подмешивая старые правки.

Для переноса дерева задачи из yEd открой нужную `/tracker/{key}`, затем меню схем → «Заменить из файла», выбери `.graphml` и подтверди замену. Промежуточный JSON не нужен. Адрес и ключ задачи останутся прежними; текст корня станет названием, зелёные узлы сохранят статус `done`, порядок детей определится их расположением в yEd. Выравнивание текста будет левым. GraphML можно также открыть как новую схему; прямая запись в исходный GraphML не поддерживается.

У файла на диске действие «Сохранить как внутреннюю» завершает совместную сессию, записывает принятые изменения в файл и открывает независимую внутреннюю схему. Исходный файл остаётся на диске, но больше не получает правки редактора. При ошибке переключения нет; завершённой файловой сессией можно поделиться заново. Участники не переходят в новую внутреннюю схему автоматически. Нужны имя и соединение.

Для прямой записи в исходный файл нужны HTTPS или localhost и браузер с File System Access API, например Chrome/Edge. Через обычный HTTP на сетевом hostname доступны скачивание и импорт копий, но разрешение браузера не включает запись в исходный файл. При открытии предоставь разрешение на чтение и запись. Файл сохраняется автоматически, состояние видно в верхней панели; `Ctrl+S` сохраняет немедленно. Ошибка записи или внешнее изменение файла показываются явно. Приложение не перезаписывает обнаруженное внешнее изменение: скачай копию своей работы или открой файл заново.

Содержимое файловой схемы не записывается в SQLite, IndexedDB или журнал sessionStorage и не появляется в каталоге. Браузер запоминает только дескриптор файла и служебные сведения о сессии. После обычной перезагрузки и `Ctrl+F5` файл открывается по прежнему адресу. Если браузер сбросил разрешение, нажми «Продолжить работу с файлом» — выбирать файл повторно не нужно. Если файл удалён или данные сайта очищены, выбери его заново. При закрытии вкладки с незаписанными изменениями появляется предупреждение; при аварии браузера последние изменения могут потеряться.

«Поделиться сессией» показывает постоянную ссылку `/file/session/{id}` в диалоге — копируй её оттуда для участников. В адресной строке владельца остаётся `/file/local/{id}`. Перезагрузка, повторный выбор файла и перезапуск сервера не меняют эти адреса: открытие файла владельцем восстанавливает совместную работу. Секрет владельца остаётся в браузере, SQLite хранит только ID и хеш секрета. Ссылка не даёт прямого доступа к диску. Держи вкладку владельца открытой: только она пишет файл. Вторая вкладка ссылки сессии становится участником, а повторное открытие того же файла для записи блокируется через Web Locks. Блокировка действует в пределах одного origin; другие браузеры, адреса публикации и внешние программы ею не охвачены.

Содержимое комнаты находится лишь в оперативной памяти, обновления передаются через `file-collaboration` относительно корня приложения. При отсутствии владельца или ошибке записи правки гостей приостанавливаются, но просмотр и скачивание доступны. Через пять минут отсутствия владельца, при явном завершении или перезапуске сервера содержимое комнаты удаляется, а постоянная ссылка сохраняется. Открытие файла владельцем восстанавливает комнату из файла с отдельным внутренним поколением. Свежая вкладка участника показывает «Ожидаем владельца файла» и подключается автоматически. Уже открытая вкладка со старым снимком предлагает скачать копию правок и явно открыть актуальную схему; старые обновления в новое поколение не принимаются. Явное завершение приостанавливает доступ до повторного открытия или приглашения, но не отзывает ссылку. Внешнее изменение файла останавливает возврат в живую комнату без перезаписи.

У адресов `/file/local/{id}` и `/file/session/{id}` один ID, различается только режим открытия. Сохраняй SQLite-базу сервера и данные сайта в браузере владельца: они содержат привязку постоянной ссылки. ID не записывается в сам файл: после очистки данных сайта или в другом браузере повторный выбор получит другую привязку. Миграция прежних раздельных ID не предусмотрена.

Ручная проверка в Chrome/Edge через localhost или HTTPS:

. Скачай дерево с жёлтыми и зелёными узлами и переносами строк; открой копию в системе и сравни содержимое.
. Открой тот же файл в режиме редактирования на диске, разреши запись, измени корень и дождись «Сохранено». Нажми `Ctrl+F5`: файл должен открыться вновь, при необходимости — после кнопки повторного разрешения. Проверь содержимое файла другим редактором.
. Измени файл снаружи и внеси правку в браузере: должно появиться предупреждение без перезаписи внешнего изменения.
. Нажми «Поделиться сессией»: локальный адрес владельца не должен измениться. Пригласи вторую вкладку ссылкой из диалога; проверь сохранение её правок в файл. Перезагрузи владельца: локальный адрес и ссылка приглашения должны сохраниться, а редактирование участником — возобновиться. Попытка открыть тот же файл для записи в третьей вкладке должна сообщить, что он занят.
. Закрой вкладку владельца и перезапусти сервис с прежним каталогом данных. Открой ссылку участника: появится ожидание владельца. Открой файл владельцем по прежнему локальному адресу: участник должен подключиться автоматически, а «Поделиться сессией» — показать прежнюю ссылку. Вкладке участника со старым снимком нужно явно открыть актуальную схему.
. В двух вкладках системной схемы выполни замену; проверь одинаковый результат, прежний URL и отсутствие старой undo-истории.

Автоматические проверки: `npm test`, затем `npm run build` и `npm run test:e2e`. Файловые сценарии находятся в `tests/e2e/files.spec.ts` и `tests/e2e/deletion.spec.ts`: запись проверяется настоящим браузерным WritableFileStream в тестовом OPFS; нативные диалоги выбора/сохранения и разрешения заменены тестовым адаптером. Восстановление дескрипторов из IndexedDB проверяется в отдельном обычном профиле Chromium, а не в incognito-контексте; профиль удаляется после теста. Вручную также проверь перенос через системный диалог сохранения, отказ разрешения, отмену выбора и дальнейшее автосохранение в выбранный файл.

=== Клавиатура и мышь

Выбери клеточку кликом; дальше можно работать с клавиатуры. Холст занимает всё окно под компактной верхней панелью. Кнопка «?» открывает справку «Клавиши», меню «⋯» — редкие действия с выбранной клеточкой. Undo/redo и «Вся схема» доступны прямо в верхней панели.

Корень публикации (`/` или, например, `/decompose/`) открывает титульную страницу с описанием инструмента, возможностей и режимов работы. Кнопка «Начать работу» или `Ctrl+O` открывает выбор схемы без блока текущего документа. В редакторе этот же диалог открывается нажатием названия схемы со стрелкой в верхней панели. Название схемы меняется редактированием корня. Ссылка `diagram/{id}` от корня приложения открывает конкретную схему и подходит для совместной работы; одинаковые названия допустимы.

[WARNING]
====
Основной схемы больше нет. При запуске сервер удаляет прежний документ `main` из SQLite, а приложение очищает его браузерный кеш и незавершённые правки этой вкладки. Отменить это удаление нельзя; если данные нужны, до обновления скачай схему или сохрани резервную копию SQLite. Остальные схемы, задачи, файлы и профиль участника не затрагиваются. Старые ссылки `diagram/main` и `?diagram=main` недействительны.
====

Адреса относительно корня приложения: `diagram/{id}` — системная схема, `tracker/{key}` — задача, `file/local/{id}` — локальный файл, `file/session/{id}` — совместная файловая сессия. Локальная ссылка восстанавливает дескриптор только в браузере, где выбран файл; для приглашения нужен адрес сессии. Старые ссылки с параметрами `diagram`, `localFile` и `fileSession` продолжают работать и заменяются каноническим адресом без лишнего шага в истории. Идентификаторы и данные не меняются. Прямое открытие вложенных адресов поддерживается и под префиксом reverse proxy; offline-перезагрузка требует ранее загруженного документа и оболочки на localhost или HTTPS.

Системные схемы хранятся в одном `decompose.sqlite`, но используют независимые документы Yjs, presence и IndexedDB-кеши. Их создание требует сервера. Уже загруженные системные схемы доступны offline по своим ссылкам; сохранённый список может быть неполным. Файловые схемы не входят в этот каталог и не сохраняются в SQLite или IndexedDB. Переключение и кнопки браузера «Назад»/«Вперёд» работают без перезагрузки страницы; история undo/redo при смене схемы очищается. Общего workspace и разграничения доступа нет.

Для задачи трекера открой `tracker/MC-99636` относительно корня приложения (например, `/decompose/tracker/MC-99636`): при первом посещении после знакомства создаётся отдельное дерево с ключом в корне. Замени текст корня описанием — он станет названием, адрес останется прежним. Повторные открытия не меняют содержимое. Ключи нечувствительны к регистру; внешняя система трекера не вызывается.

В окне выбора раздел «Задачи» отделён от обычных схем. Без поиска он показывает 20 последних изменённых деревьев; поиск ищет вхождение в ключ или текст корня по всем задачам, включая русские названия. Кнопка «Показать ещё» открывает следующую порцию. Ранее загруженные задачи доступны offline по тем же адресам; offline-поиск использует неполный сохранённый каталог. Привязки и поисковый индекс хранятся в той же SQLite и входят в её резервную копию; таблица создаётся автоматически при обновлении.

Для переноса дерева из yEd открой список схем → «Файлы» → «Новая схема из файла» и выбери `.graphml` (до 5 МиБ и 1000 узлов). Импорт создаёт отдельную схему, сохраняя текст, иерархию и вертикальный порядок детей; зелёные узлы получают статус `done`, остальные — `open`. Раскладка вычисляется заново: точные координаты и оформление не переносятся. Поддерживаются `ShapeNode` и `GenericNode` в одном направленном дереве без групп и циклов. Нужны имя пользователя и соединение с сервером; ограничения формата описаны в xref:docs/product.adoc[описании продукта].

Смотреть схемы можно без имени. Перед первым изменением или созданием схемы приложение предлагает представиться. Имя сохраняется в этом браузере между перезагрузками и схемами; изменить его можно через собственный значок в верхней панели. Гости видны только общим числом, без индивидуальных значков и выделений. Это не регистрация: в другом браузере нужно представиться заново, перенос профиля не предусмотрен.

* `Tab` — создать child; `Enter` — создать sibling (у root sibling нет).
* Стрелки — parent/child и предыдущий/следующий sibling.
* `Ctrl+↑/↓` — изменить порядок; `Ctrl+→` — indent под предыдущий sibling; `Ctrl+←` или `Shift+Tab` — outdent.
* `F2` или двойной клик — редактировать; `Space` — изменить статус.
* В редакторе `Shift+Enter` вставляет мягкий перевод строки, `Enter`, `Ctrl+Enter` или уход фокуса сохраняет текст без создания узла; `Tab` сохраняет и создаёт child, `Escape` отменяет draft. Для нового sibling после сохранения нажми `Enter` ещё раз. Переносы из буфера и GraphML также сохраняются.
* «⋯» → «Схема» → «Текст карточек по центру» переключает горизонтальное выравнивание всех карточек и редакторов между левым краем и центром. Настройка сохраняется отдельно для каждой схемы, синхронизируется между участниками и поддерживает undo/redo и offline-работу. По умолчанию используется левый край.
* `Delete` или кнопка «Удалить» — сразу удалить узел с поддеревом без подтверждения; `Ctrl+Z` восстанавливает удалённое.
* `Ctrl+Z` — отменить, `Ctrl+Shift+Z` или `Ctrl+Y` — повторить. Кнопки ↶/↷ доступны на панели. В редакторе отменяется только draft, на схеме — собственные сохранённые действия (текст, статус, создание, перемещение, удаление). История отдельная для каждой вкладки и очищается при перезагрузке; создание пустой клеточки и сохранение текста — два шага. Чужие действия не попадают в историю; конфликтующий шаг может отмениться частично или быть пропущен.
* `Escape` на схеме возвращает фокус на меню действий «⋯» в верхней панели, откуда доступна обычная Tab-навигация.
* Клик активирует клеточку. Мышью тяни за любую часть активной клеточки вне редактирования текста: линия показывает место вставки среди детей того же родителя. Порядок сохраняется при отпускании; `Escape` отменяет перестановку. Неактивная клеточка при перетягивании перемещает холст и не становится активной после отпускания. Root и единственный ребёнок также перемещают холст, а не переставляются.

* `Ctrl+O` — открыть выбор схемы, предварительно сохранив редактируемый текст клеточки. Пока фокус в приложении, сочетание заменяет браузерное открытие файла. Поверх открытого диалога другой не открывается.

На macOS вместо Ctrl поддерживается Command. Presence предупреждает о редактировании и блокирует вход в занятый редактор online; это мягкая блокировка, не серверная гарантия.

== Структура

* `src/domain/` — схема Yjs, операции и чистая проекция валидного дерева;
* `src/client/` — интерфейс React Flow, локальные drafts, ELK и offline session;
* `src/server/` — один HTTP/WebSocket-сервис и SQLite;
* `src/shared/` — формат идентификаторов и ссылок схем, проверка дерева для импорта;
* `public/` — готовые иконки сайта; `assets/branding/` — исходник логотипа;
* `tests/unit/`, `tests/e2e/` — проверки модели и пользовательских сценариев;
* `tests/fixtures/` — обезличенные примеры импортируемых файлов;
* `docs/` — требования, архитектура, инварианты и открытые вопросы.

Ограничения MVP: без типов узлов, reparent мышью, collapse, долговременной истории, поиска внутри дерева и экспорта в графические форматы. Геометрия вычисляется локально; порядок детей хранится в модели.

Подготовленные варианты: `public/brand/logo.png` для верхней панели, `public/favicon.ico` с размерами 16, 32 и 48 px, `public/favicon-32.png` и `public/apple-touch-icon.png`. Белые поля удалены, для значка и favicon фон прозрачен; форма рисунка сохранена.

Для повторной конвертации запусти `python scripts/prepare-branding.py` в окружении с Pillow. Для обычной сборки Python и Pillow не нужны: готовые иконки хранятся в репозитории.

== Лицензия

Исходный код и документация Decompose распространяются по лицензии Apache License 2.0. Полный текст находится в файле `LICENSE`, сведения об авторских правах — в `NOTICE`.

Production-сборка использует сторонние библиотеки под совместимыми открытыми лицензиями. Их перечень и полные тексты лицензий находятся в `THIRD_PARTY_NOTICES`, а исходные лицензионные файлы сохраняются в каталогах соответствующих npm-пакетов. Команда `npm run licenses` обновляет файл после изменения `package-lock.json`, а `npm run licenses:check` проверяет его актуальность. Docker-образ содержит все три файла, frontend-сборка публикует их в каталоге `licenses/`.
